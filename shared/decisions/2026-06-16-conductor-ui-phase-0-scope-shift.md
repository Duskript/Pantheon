# 2026-06-16 — Conductor UI Phase 0 Scope Shift (P0a → Phase 1, Iris → Marvin)

## Date
2026-06-16

## Decision

The Conductor UI build's Phase 0 was restructured mid-dispatch after Iris's worker crashed twice on skill resolution. The P0a mock re-inspection task was removed from Phase 0 and folded into Phase 1's shell work. Phase 0's owner changed from Iris to Marvin.

## What was decided

1. **P0a (mock re-inspection) is removed from Phase 0.** Folded into Phase 1 as the first deliverable of the shell work. The shell build reads the mock as part of the build and writes `docs/mock-inspection.md` as a side-effect.
2. **Phase 0 is now 5 tasks** (was 6). P0b is already shipped (signed off earlier today). The remaining Phase 0 work is scaffold + ledger_client + API clients + theme tokens + routing.
3. **Phase 0 owner is now Marvin** (was Iris). Marvin has the required skills (`pantheon-dev-workflow`, `olympus-ui`) and doesn't crash on the planning skills the task originally loaded (`build-spec-authoring`, `thoth-qa-gate`).
4. **The bad skills are stripped from the Phase 0 task body** (direct SQLite update — the kanban CLI doesn't expose a skills-edit flag). Marvin's task loads only `pantheon-dev-workflow, olympus-ui`. The Thoth QA review follow-on (a separate task, auto-generated by t5) has the `thoth-qa-gate` skill.
5. **The v1.1 plan §4 (Phase 0) and §5 (Phase 0 file table) are patched** with the scope shift, dated, and explained.

## Rationale

- **The mock re-inspection is a planning artifact, not a build artifact.** The information (5 screens, 14-connector catalog, per-type config forms, reusable parts vs parts to rebuild) is already in v1.1 plan §3. The formal `docs/mock-inspection.md` doc is overhead.
- **Iris's worker crashes are uninvestigated.** The signature ("pid not alive" on consecutive runs) suggests a profile/state issue that would block all of her work, not just this task. Reassigning to Marvin sidesteps the issue; Iris stays available for Phase 1+ UI/UX work where her role is clearer.
- **The scaffold work is coder work.** Vite + React + TS + ledger_client + API clients are all backend/frontend code. Marvin's lane. Iris's lane is the visual layer (shell, theming, route design) — that's Phase 1+.
- **The skills bug is a real class of issue.** The "skills must be installed in profile, not just in external_dirs" gotcha hit Iris. The fix was direct SQLite intervention because the kanban CLI doesn't expose a skills-edit flag. **This is a tool gap to flag for future work.**

## Alternatives considered

- **(a) Investigate Iris's crash and retry.** Rejected: would block the chain on debugging, the build is critical-path.
- **(b) Keep Phase 0 with Iris, strip the bad skills only.** Rejected: doesn't fix the worker crash issue, just postpones it.
- **(c) Reassign all of Iris's work (Phase 1, 2) to Marvin.** Rejected: too much scope shift, Iris's UI/UX expertise is needed for the visual layer.
- **(d) Skip P0a entirely (don't fold into Phase 1, just remove it).** Rejected: the inspection is still valuable, it's just better done as part of the shell work.
