but every root-profile schedule is one hour off local wall clock while MDT holds.

`timezone: 'America/Boise'` (or `''`, matching `profiles/thoth/config.yaml:456`).

`America/Boise` = `MDT -06:00` in September. The root profile's cron honours the
setting; the named profiles do not. So `0 5 * * *` in root fires at 06:00 MDT and
`0 6 * * *` in thoth fires at 06:00 MDT — identical instants:

```

thoth 81cbb7464d79  0 6 * * *  next_run_at 2026-09-25T06:00:00-06:00
```

**Scope:** 55 root-profile jobs; 29 enabled already stamped `-07:00`, 10 more
enabled with stale `-06:00` next-runs that will follow. Fleet-wide offsets:
`-06:00` 191 / `-07:00` 57 / `+00:00` 23 — all 57 `-07:00` are root-profile.
Affected by name include `Hades Nightly Consolidation` (`0 0` → 01:00 MDT),
`Dawn Patrol Digest Delivery` (`55 5` → 06:55 MDT), `Dawn Patrol Report
(archive)` (`0 5` → 06:00 MDT).

**Reversibility:** trivial and instant — one config value; a restart re-reads it.
The only care needed is that jobs whose `next_run_at` is already stamped in the
old frame get recomputed, so expect one cycle of transition.
