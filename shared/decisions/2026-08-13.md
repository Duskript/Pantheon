# Decisions — 2026-08-13

## Apollo notification fallback for Genre-Lexicon cron

**Decision:** Because `god-notify` returned `Authentication required`, the WebUI daemon reported stopped, and local WebUI sessions had zero valid unexpired entries, Apollo used the established direct append fallback to `~/.hermes/notifications.json` for the Genre-Lexicon completion notice.

**Rationale:** The scheduled cron job must notify on knowledge-base updates. With the canonical POST path blocked by auth/no valid sessions and the daemon stopped, direct append is the only verified path that preserves the notification in the WebUI bell store.

**Evidence:**
- `god-notify Apollo info ...` returned `Failed to send notification ... {"error":"Authentication required"}`.
- `~/pantheon/webui/ctl.sh status` returned `hermes-webui — stopped`.
- Session check returned `sessions total=69 valid=0`.
- Direct append verification returned notification count `43`, last title `Genre-Lexicon expanded`, source `god:apollo`, dismissed `False`.

**Alternatives considered:** Retry authenticated POST with an existing cookie; not possible because no valid sessions were present. Suppress notification; rejected because Apollo SOUL requires a notification after knowledge-base updates.

**Reversibility:** Fully reversible. Once WebUI auth/daemon status is restored, return to canonical `god-notify` POST path. The appended notification can be dismissed normally in the UI.
